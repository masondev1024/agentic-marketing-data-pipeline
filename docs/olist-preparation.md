# Olist 실제 데이터 연결 준비

후속 상태: **Docker PostgreSQL 원본 검증·마트·게시 복구·결정론적 진단까지 로컬 검증 완료**.
[실행 문서](olist-docker.md)와 [검증 증거](../evidence/olist-local-v1.json)를 따른다.
아래 내용은 원본 확보 당시의 준비 기록과 계약 초안이다. 수행 주체는 조력자다.
기존 합성 데이터 릴리스의 419개 테스트 통과를 실제 데이터 처리 검증으로 확대하지 않는다.

## 지금까지 완료한 로컬 기반

- 고정한 공개 LLM의 추론·실행 기록, 문서 검색과 보류, HTTP API·대기열·timeout/재시작.
- 합성 광고비·주문·환불의 Bronze/Silver/Gold, 중복 제거·fanout 방지·과거 재계산·원자 게시.
- 불변 scope·읽기 전용 도구·숫자와 증거 ID 검증, 횟수·시간·출력 한도.
- 실제 Qwen 도구 선택과 결정론적 기준선 비교: 기준선 3/3, 모델 0/3. 모델은 실험용이다.
- SQLite LangGraph의 새 프로세스 재개·제안 검토·crash 복구. 외부 쓰기 기능은 없다.
- [최종 검토](../evidence/marketing-main-review.json): 전체 419개·Ruff 통과,
  이후 문서/릴리스 검사 11개 통과. AWS는 선택 설계, 자동 formal 평가는 미실행이다.

## 확보한 원본과 사용 경계

[Olist 커머스](https://www.kaggle.com/datasets/olistbr/brazilian-ecommerce)와
[Olist 마케팅 퍼널](https://www.kaggle.com/datasets/olistbr/marketing-funnel-olist)을
공개 다운로드 경로에서 인증 없이 받았다. 두 데이터 카드의 라이선스 표기는
CC BY-NC-SA 4.0이며, 원본 출처·라이선스와 가공 이력을 유지한다.
원본 ZIP/CSV는 Git 제외 경로 `work/olist-intake/`에만 보관한다.
[수집·파일 해시·프로파일](../data/olist/intake-v1.json)에는 원본 행/식별자/리뷰 본문을 넣지 않았다.
상류의 숫자 버전은 아직 확인하지 못했고, 내려받은 정확한 바이트를 SHA256으로 고정했다.

| 확인 항목 | 실제 관측 |
|---|---:|
| CSV 파일 | 11개 |
| 주문 / 주문상품 | 99,441 / 112,650행 |
| 마케팅 리드 / 계약 기록 | 8,000 / 842행 |
| 계약 판매자 중 커머스 판매자와 연결 | 380 / 842명 |
| 커머스 판매자와 연결되지 않는 계약 판매자 | 462명 |
| 유입 경로가 빈 리드 | 60행 |

검사한 후보 키에는 중복이 없었지만, 이를 모든 표의 grain 검증 완료로 해석하지 않는다.
예를 들어 리뷰와 지리정보는 아직 고유 키를 확정하지 않았다. 첫 제품에서는 제외한다.
공개 데이터는 익명화된 과거 표본이다. 원천 회사 전체 모집단이나 현재 운영 상태가 아니다.

## 첫 데이터 제품과 계약 초안

업무 질문: **어떤 유입 경로의 판매자가 계약하고, 계약 이후 어떤 주문 실적이 관측되는가?**
소비자의 광고 클릭→구매 퍼널과 구분한다. 기본 모델은 다음 세 grain이다.

- 리드: `mql_id` 한 행. 계약은 `mql_id`로 연결하고 유입 경로 누락을 별도 표시한다.
- 계약 판매자: 계약 키와 `seller_id`를 보존. 중복·다중 계약이 생기면 임의로 한 행을 고르지 않는다.
- 주문상품: `(order_id, order_item_id)` 한 행. 판매자·주문별 집계 후 리드/계약 마트에 연결한다.
  결제와 상품 원본을 그대로 조인해 금액이 늘어나는 것을 방지한다.

첫 지표는 공개 표본 내 계약 관측률, 계약 후 첫 관측 주문까지의 기간, 관측 주문수다.
채널별 30일 상품 거래액은 금액·관찰 기간 계약 확정 후 추가한다. 상품 거래액을
Olist 플랫폼 수익이나 광고 귀속 매출로 부르지 않는다. 광고비·환불 원장이 없어
ROAS·CAC·환불 차감 매출을 계산하지 않으며 `declared_monthly_revenue`를 실매출로 쓰지 않는다.

금액은 소수 문자열을 Decimal/최소 화폐 단위로 정규화할 예정이다. 원자료에 화폐 코드가
없으므로 통화 해석의 근거를 먼저 기록한다. KRW로 이름만 바꾸거나 float로 집계하지 않는다.
시각에도 offset이 없으므로 원문을 보존하고 timezone 해석을 확정하기 전 UTC/KST로 바꾸지 않는다.

연결되지 않은 462명은 **표본 간 관측 범위 미확인**이다. 매출 0원·계약 실패로 대체하지 않는다.
누락 행을 버리는 inner join 대신 연결 상태와 분모를 보존한다.
주문 관측 종료는 2018-10-17, 계약은 2018-11-14까지 있어 관찰 기간도 다르다.
30일 지표에는 관찰 기간 부족 상태를 표시하고, 구매가 계약보다 앞선 행도 별도로 점검한다.
최대 관측 날짜는 원천 완전성을 보증하는 watermark가 아니며 다운로드 시각과 구분한다.

## 구현 순서와 완료 조건

1. **별도 Olist 계약/입구**: `data/olist/` 계약과 `src/llm_ops_lab/olist/` 어댑터를 추가한다.
   지금은 어댑터가 없다. 필수 파일·열·키·타입·해시 변경과 ZIP 손상을 명시적으로 거절한다.
   같은 원본은 같은 수집 ID가 되고 실패한 시도는 이전 원본과 제품을 덮어쓰지 않는다.
2. **정규화와 마트**: 후보 키·참조 누락·금액·시각을 검증하고 리드/판매자/주문상품 grain을
   유지한다. 원본 대비 건수·키·금액 대사, 중복 배달 불변, fanout 방지, 미연결 462명 보존,
   관찰 기간 부족·유입 경로 누락 표시를 확인한 뒤 제품을 게시한다.
3. **진단 연결**: Olist 지표 정의와 품질 결과에 맞는 읽기 전용 도구/결정론적 기준선을 먼저
   추가한다. 그 후 작은 고정 사례로 실제 모델을 비교한다. 기존 ROAS 결론 enum을 재사용해
   계약 전환율로 몰래 해석하지 않는다. 새 실제 데이터의 모델 품질은 아직 측정하지 않았다.

기존 `marketing/contracts.py`는 KRW/KST, `diagnostics.py`는 ROAS 전용 비교다.
따라서 원천별 어댑터를 분리하고 검증·불변 게시·읽기 전용·복구 원칙을 재사용한다.
합성 수용셋은 장애 검증용으로 보존한다. 첫 연결에는 AWS나 추가 모델 다운로드가 필요 없다.

## 사용자가 할 일

**현재 다운로드·로그인·API 키 전달은 필요 없다.** 이미 파일을 확보했다.
다운로드를 직접 다시 할 경우 위 두 공개 페이지에서 ZIP을 받고 별도 폴더에 보존하면 된다.
기존 ZIP을 덮어쓰지 않고 새 해시/버전으로 검토한다. 이후 비공개 광고·쇼핑몰 계정을
연결할 때만 접근 권한과 실제 지표 정의를 별도로 확인한다.
