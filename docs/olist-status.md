## 2026-10-07 조사 에이전트·HTTP 연결 추가

현재 진행 상태는 다음과 같다. 아래의 이전 460개 검증 기록은 기존 데이터 제품 릴리스이며

최종 자동 검사는 **496개 통과(실제 PostgreSQL 검사 13개 포함), Ruff 통과**다.

[테스트 출력](../evidence/olist-investigation-tests-v2.txt)을 보존했다.

| 순서 | 구현·검증 범위 | 남은 작업 |
|---|---|---|
| 1. 지표 계약 | 별도 버전의 통화·시간대·완전성 정책과 허용/제한 지표 정리 | 데이터셋에 해당하는 확정 근거 확보 시 승격 |
| 2. LLM 조사 | 모델이 네 종류의 읽기 도구를 선택하는 루프, 근거·예산·출력 검증, CLI·6사례 평가기 | 실제 Qwen 생성 품질 평가 |
| 3. HTTP 연결 | `/v1/investigations`, 기존 GPU worker/큐 재사용, 버전·정책·모델·요청 로그 연결 | 실제 모델을 포함한 HTTP 검증 |
| 4. 파이프라인 조사 | 실제 실행 이력 조회, 고정 의존 그래프, 오류와 원인·현재 게시 상태 구분 | 새 모델 루프의 영속 체크포인트·재개와 추가 실행 계측 |
| 5. AWS | 런타임 이전·권한·예산·운영 조건 문서화 | 모델/API 검증 뒤 인프라 구체화와 배포 승인 |

신규 PostgreSQL 검사는 조사 중 새 게시가 생겨도 동일 스냅샷·버전을 유지하는지,
쓰기 계정을 거부하는지, 모델이 선택한 도구만 조회하는지 확인한다.
실제 DB의 최근 다섯 실행에서 `mart / QueryCanceled` 실패와 현재 정상 게시 버전을 확인했다.
이는 고정 도구 조회 증거다. 실제 모델이 진단에 성공했다는 결과로 사용하지 않는다.

Mac 메모리 압력이 경고(`kern.memorystatus_vm_pressure_level=2`)로 확인되어 신규 Qwen
평가·실제 모델 HTTP 실행은 아직 수행하지 않았다. 단위 테스트의 scripted model 결과와
실제 모델 결과를 분리한다. 상세 실행법은 [조사 API](olist-agent-service.md),
지표 제한은 [정책](olist-metric-policy.md), 단계 그래프는 [lineage](olist-lineage.md),
클라우드 조건은 [AWS 이전 판단](olist-aws-readiness.md)을 참고한다.

## 2026-10-07 Olist 실제 데이터·Docker PostgreSQL

조력자가 원본 검증, 정규화/마트, 원자적 게시·복구, 결정론적 근거 진단까지 구현하고
**실제 PostgreSQL 통합 검사를 포함해 460개 테스트 통과, Ruff 통과**를 확인했다.
로컬 컨테이너만 실행했으며 AWS/Cloudflare 리소스는 만들지 않았다.
[증거](../evidence/olist-local-v1.json), [진단 결과](../evidence/olist-diagnosis-v1.json),
[운영 방법](olist-docker.md)을 참고한다. 기존 docs/status.md의 419개는 이전 합성 데이터 릴리스의 기록이다.

원본 11개 CSV/두 ZIP의 해시·CRC·구조·선택 테이블 의미 계약을 검사하고, 리드 8,000·계약 842·
주문 99,441·주문상품 112,650건을 적재했다. 연결 판매자 380/미연결 462, 누락 origin 60을
보존한다. 미연결 주문수는 NULL이다. 동일 버전 재사용, 실패 시 이전 정상 버전 유지,
read-only 역할, Bronze 재실행, 컨테이너 재시작, 새 DB 복원의 10개 테이블 행 해시/건수 대사를 검증했다.

실제 새 버전 적재에서 낡은 planner 통계로 127.21초 후 timeout을 재현했고, 적재 직후
ANALYZE로 수정한 실행은 4.48초에 게시됐다. 단일 로컬 재현 결과이며 SLA나 일반 성능 수치가 아니다.
모델 실행은 하지 않았다. timezone/통화/원천 완전성은 미확정이고, source-clock 계약 전/후 비교는
그 한계를 명시한 조건부 관측이다. 검증된 30일 귀속·ROAS·CAC·자동 장애 복구는 제공하지 않는다.
기존 HTTP API/SQLite graph에 이 신규 경로를 붙이는 것은 후속 범위다.
