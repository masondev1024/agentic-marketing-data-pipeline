# 실습 5 — 프롬프트만 바꾼 비교 실험

## 결과와 판단

새 프롬프트 grounded-v2는 기본값으로 채택하지 않았다. 개발셋에서 필수 내용과 근거 충실성을
동시에 충족한 문항 수가 늘지 않았고, 기존에 맞히던 정의 문항에서 퇴행이 발생했다.
이번 번호는 학습 단계이며 실제 실행은 2026-10-06에 진행했다.

| 검사 | baseline | grounded-v2 |
|---|---:|---:|
| 검색 선택/보류 일치 | 18/20 | 18/20 |
| 필수 내용 + 근거 충실성 통과 | 4/15 | 4/15 |
| 생성한 범위 내 답변의 두 문장 형식 | 0/14 | 2/14 |
| 범위 밖 질문 생성 전 보류 | 4/5 | 4/5 |
| 실행 오류 | 0/20 | 0/20 |

15문항은 정답 문서가 있는 질문이며, 검색에서 누락한 1문항도 분모에 남겼다.
형식은 실제 생성한 범위 내 14문항에 대해서만 평가했다. 범위 밖 5문항은 별도 보류 기준을 적용했다.
필수 내용/근거/형식은 assistant의 수동 판정이다. 독립 평가자의 합의나 일반화 성능은 아니다.
보수적인 기준으로 필수 요소 누락과 질문 반복도 실패로 분류했으며 문항별 이유를 공개한다.

## 작성한 채점표

사용자가 실행한 배치 `6e5127a2-bff7-45e9-8455-7503a088fcca`의 review.md를
20문항 모두 작성했다. 실행자 learner와 검토자 assistant를 구분했다.
원래 채점표는 review.unreviewed.md에 보존했고, 판정은 manual-review.json에도 저장했다.
원본 추론 JSON, summary.json의 자동 지표는 수정하지 않았다.

## 가설과 통제 조건

관측된 문제는 문서가 제대로 전달돼도 부정 표현·단위·필수 항목이 생성 과정에서 바뀌거나
빠지는 것이다. 단순히 모델 크기만의 문제라고 확정하지 않았다.
명시적으로 의미 보존을 지시하면 오류가 줄어드는지 확인하기 위해 다음 후보를 만들었다.

> 참고 문서에서 질문에 직접 답하는 사실을 찾아 한국어로 답하세요.
> 원문의 긍정과 부정, 조건, 숫자와 단위를 그대로 보존하세요.
> 질문이 요구한 항목을 빠짐없이 설명하되 문서에 없는 사실은 덧붙이지 마세요.
> 특정 정보가 문서에 없으면 그 정보가 없다고 답하세요.
> 제목이나 목록 없이 정확히 두 문장으로 답하고 답변 작성 지시는 출력하지 마세요.

기존 문서 내 지시 무시 안내는 두 버전에서 동일하게 유지한다. 정답이나 특정 문항 수치를
후보 프롬프트에 넣지 않았다. 평가 데이터와 검색기를 수정하지 않았다.

프롬프트 선택 기능을 추가한 같은 코드에서 두 버전을 다시 실행했다.
질문·루브릭·문서·모델 revision·온도·토큰·seed·실행 코드·lockfile 해시가 일치함을 검증했다.
모델에 전달한 사용자 메시지도 문항마다 동일하고 시스템 메시지만 달랐다.
새 코드의 baseline은 사용자 배치와 전체 20문항의 출력 및 실제 메시지가 동일했다.
모델 추론은 문항별로 순차 실행했다. 두 GPU 배치를 동시에 돌리지 않았다.

## 개선과 퇴행을 함께 보기

- idempotency-recovery: '장애 후 재시도를 금지해야 한다'에서 '재시도를 금지하는 것이 아니며
  중복 효과를 막아야 한다'로 개선했다. 사실/근거 통과로 바뀌었지만 한 문장이다.
- idempotency-definition: 기존에는 정의가 맞았으나 후보는 질문을 그대로 반복했다.
  사실/근거 동시 통과 문항에서 탈락했다.
- retry-policy: 두 버전 모두 재시도 간격을 5회라고 답했다. 단위 오류가 해결되지 않았다.
- retry-auth: 후보는 두 문장을 출력했지만 문서가 일시적인 오류/backoff를 고려하지 않는다는
  반대 주장을 했다. 형식 개선을 사실 개선으로 해석하지 않는다.
- backfill-validation: 후보가 검사 항목을 더 많이 나열했지만 필수 값 누락을 명시하지 않고
  질문형으로 끝나 필수 내용 전체 충족에는 실패했다.

검색에서 실패한 retry-unknown-seconds와 unknown-private-backfill은 그대로다.
이번 변경은 검색 전 보류 기준에 영향을 주지 않으므로 검색 개선을 주장하지 않는다.

실행 전 세운 채택 기준은 필수 내용+근거 동시 통과 증가, 기존 통과 문항 퇴행 없음,
retry-policy 및 idempotency-recovery의 내용/근거 통과였다. 모두 충족하지 못해 기본값을 유지한다.
한 번의 후보 실험이 모든 프롬프트 개선 가능성을 부정하는 것은 아니다.

## 재현 명령

기존 프롬프트:

```sh
uv run --locked python -m llm_ops_lab.evaluation --offline \
  --prompt-variant baseline --temperature 0 --max-tokens 256 --seed 42
```

실험 후보:

```sh
uv run --locked python -m llm_ops_lab.evaluation --offline \
  --prompt-variant grounded-v2 --temperature 0 --max-tokens 256 --seed 42
```

기본값은 baseline이다. 단일 질문의 llm-lab에도 같은 옵션을 사용할 수 있다.
후보를 선택하면 manifest와 각 실행 JSON에 prompt_variant=grounded-v2,
문서 프롬프트 버전 document.v2가 기록된다. 기존 v1 기록은 보존한다.

assistant 검증 배치:
- baseline: `714d5ee7-6129-4607-980c-5f489149848b`
- grounded-v2: `3a3e590f-5f96-44fc-9a36-59871f01aa32`

## 검증 범위와 다음 실험

pytest 59개와 Ruff 통과. 테스트는 기존 프롬프트 보존, 사용자 메시지 동일성,
옵션 전달과 버전 기록 및 잘못된 옵션 거절을 검증한다. 답변 품질은 실제 40문항 실행으로 확인했다.
훈련이나 모델 가중치 변경은 하지 않았다. 단일 seed의 공개 개발셋이라 테스트셋 성능을 주장하지 않는다.

다음으로는 baseline 프롬프트와 평가셋을 고정하고 모델을 변경하는 비교가 적절하다.
선택한 모델의 라이선스, 고정 revision, 메모리와 토큰 비용을 확인한 뒤 같은 루브릭으로 평가한다.
검색 선택 실패는 모델 변경으로 자동 해결되는 문제가 아니므로 이후 검색 개선 실험으로 분리한다.
이번 단계에서 추가 모델 다운로드·파인튜닝·API 배포는 수행하지 않았다.
