# 인과관계 보존 프롬프트 비교 — 후보 비채택

`grounded-v3`를 구현하고 실제 추론으로 비교했다. 재시도 제한 질문은 개선됐지만,
기존 정답 3개가 실패로 바뀌어 기본값으로 채택하지 않았다. 기본값은 `baseline`이다.
이번 번호는 학습 단계이며 9일간 운영했다는 의미가 아니다.

## 가설과 변경 범위

학습자의 실행 `4c6c9e5e-2e38-4526-8f3d-91d4bd7ff6c2`에서 retry.md가 선택됐으나
“일시적인 오류가 반복적으로 발생하지 않도록” 횟수를 제한한다는 잘못된 답변을 확인했다.
문서가 전달된 뒤의 생성 오류이므로 검색기와 문서를 고정했다.

후보는 문서의 행동·대상·조건·결과를 유지하고, 문서에 없는 원인·효과·보장을 추가하지 않도록
지시한다. 재시도나 특정 평가 문항의 정답은 프롬프트에 넣지 않았다.
조건·항목 누락 방지와 학습용 예시의 범위도 함께 지시했으므로, 결과는 **프롬프트 전체 변경의 효과**다.
인과관계 지시 한 문장의 독립적인 효과를 입증한 것은 아니다.

변경 파일은 context.py의 후보/버전 정의와 cli.py의 버전 기록이다. 기존 v1/v2를 보존하고
`document.v3` 또는 `manual.v3`를 명시한다. 새 모델 다운로드·가중치 변경·파인튜닝은 하지 않았다.

## 실험 설계와 통제

- Qwen3-4B 4bit 고정 revision, `scoped-v3`, 원문 문서와 scope 계약을 유지했다.
- temperature 0, max-tokens 256, seed 42, baseline 문서 래퍼를 고정했다.
- 기존 개발 20문항과 추가 검증 20문항을 두 프롬프트로 각각 실행했다.
  각 버전에서 문서 선택 대상 25개는 생성하고, 보류 대상 15개는 모델 호출 전에 보류했다.
- 총 80개 평가 사례에서 생성 오류·타임아웃·토큰 한도 도달은 없었다.
- 질문·루브릭·문서·scope·모델 revision·생성 설정·소스·lockfile 해시를 검증했다.
  문항별 검색 판정과 실제 사용자 메시지가 같고, 생성 시 시스템 메시지만 바뀌었다.
- GPU 배치는 순차 실행했다. baseline이 먼저 실행됐으므로 시간은 순서·캐시·발열 영향을 받는다.

실행 전에 정한 후보 추천 기준은 대상 질문의 내용 통과, 전체 내용 통과 증가,
기존 통과 문항의 퇴행 없음, 동일한 검색 결과, 신규 실행 오류·잘림 없음이다.
평가 후 이 기준이나 JSONL 루브릭을 바꾸지 않았다.

## 결과

| 지표 | baseline | grounded-v3 |
|---|---:|---:|
| 검색 선택/보류 일치 | 40/40 | 40/40 |
| 기존 개발셋 내용·근거 | 11/15 | 10/15 |
| 추가 검증셋 내용·근거 | 7/10 | 9/10 |
| 내용·근거 합계 | **18/25** | **19/25** |
| 생성 답변의 두 문장 형식 | 19/25 | 14/25 |
| 범위 밖 질문 생성 전 보류 | 15/15 | 15/15 |
| 실행 오류 / 토큰 한도 도달 | 0 / 0 | 0 / 0 |

내용·근거·형식은 assistant의 수동 판정이다. 평가셋은 개발에 사용됐고 독립 테스트가 아니다.
기존 개발 baseline의 20개 출력은 이전 채점 배치와 모두 동일해 동일한 판정을 유지했다.
키워드 포함 여부나 실행 성공을 의미 정확성으로 대체하지 않았다.

### 개선 4건과 퇴행 3건

| 문항 | 변화 | 근거 |
|---|---|---|
| retry-jitter | 개선 | 중복 방지라는 추가 효과가 사라지고 무작위 지연·요청 집중 완화를 설명 |
| retry-timeout | 개선 | 타임아웃이 서버 미처리의 증거가 아니라는 조건을 포함 |
| team-retry-design | 개선 | 오류 발생 방지 주장이 사라지고 무한 반복·전체 시간 예산을 포함 |
| backfill-null | 개선 | 검증이 중복을 제거한다는 주장을 없애고 임시 출력 검증 후 교체를 설명 |
| idempotency-recovery | **퇴행** | “재시도는 장애 복구 방법이 아니라”라는 원문과 반대되는 주장을 추가 |
| retry-policy | **퇴행** | jitter의 무작위 지연·요청 집중 완화라는 필수 의미를 누락 |
| retry-auth | **퇴행** | 권한/입력 오류는 입력 또는 설정 수정이 필요하다는 조건을 누락 |

기존 실패인 백필 준비의 출력 위치, 백필 동시성의 저장소 트랜잭션/스냅샷 조건,
트랜잭션 질문의 중복 확인·매출 반영·이력 저장 범위도 충분히 개선되지 않았다.
합계가 한 개 늘었어도 이미 맞히던 질문을 틀리게 만들었으므로 채택 기준은 실패다.

### 대상 질문의 실제 후보 출력

> 재시도 횟수를 제한해야 하는 이유는 일시적인 오류가 반복될 경우 시스템 부담을 줄이기 위해 최대 시도 횟수를 정하고, 무한 반복으로 인한 자원 낭비를 방지하기 위해 전체 시간 예산을 설정하기 때문이다.

오류가 발생하는 상황과 재시도를 제한하는 행동을 구분하고, 무한 반복·시간 예산을 포함했다.
시도·시간을 제한하는 효과로 부담/자원 낭비를 설명한 것으로 판정했으며 정량적인 부하 감소를
입증한 것은 아니다. **한 문장이라 형식은 실패**다.
학습자가 사용하는 `data/runbooks` 경로로 별도 CLI 추론도 실행했고 같은 출력이 나왔다.
이 추가 1회는 위 25문항 통계에 넣지 않았다.

## 채점·리뷰의 한계

독립 코드 리뷰는 후보 분리와 버전 전달을 확인했고, 아키텍처 리뷰는 개발셋 적응과
프롬프트 전체 변경의 효과라는 한계를 WATCH로 남겼다. 별도 검토자가 atomic/policy/auth
세 답변의 의미도 검토해 atomic 통과, policy/auth 필수 내용 실패를 확인했다.

판정의 경계도 공개한다. atomic의 “중복 이벤트가 처리되지 않도록”은 모호하지만 앞 문장의
중복 반영 방지 문맥으로 통과시켰다. retry-policy의 backoff/jitter를 묶은 설명은 별도 검토에서
근거 충실성도 경계성 실패로 봤다. 본 채점은 기존 baseline의 유사 표현에 적용한 관용을 유지해
근거는 통과로 뒀으나, 필수 내용이 빠졌으므로 내용·근거 동시 통과는 두 판정 모두 실패다.
백필 준비 루브릭의 출력 위치는 질문 표현보다 넓은 요구지만 이전 비교와 동일하게 유지했다.
독립적인 사람들의 합의 점수나 일반 질문의 정확도는 아니다.

테스트 **164개와 Ruff 통과**. 이는 옵션/버전/입력 보존 등 코드 검증이며 생성 품질의 증거는
위 실제 출력과 수동 채점이다. `work/`의 실행·채점 스크립트는 무시된 로컬 작업 파일이고
소스 린트 범위 밖이다. 재현에는 아래 공개 CLI를 사용한다.

## 입력량과 실행 비용

| 관측값 | baseline | grounded-v3 |
|---|---:|---:|
| 입력 토큰 중앙값, 각 25개 | 396 | 527 |
| 출력 토큰 중앙값, 각 25개 | 70 | 59 |
| 생성 시간 중앙값 | 4.03초 | 3.87초 |
| MLX 최대 메모리 | 2.98GB | 3.05GB |

문항마다 새 프로세스를 시작한 로컬 측정이며 첫 실행도 포함했다. 후보 출력이 더 짧고 실행 순서도
다르므로 후보가 더 빠르다는 결론을 내릴 수 없다. 전체 서비스 지연·p95·동시 처리 성능도 아니다.
프롬프트가 길어지면 입력량과 메모리 부담은 늘 수 있으므로 품질 개선과 함께 평가해야 한다.

## 재현과 복귀

프로젝트 루트에서 후보의 대상 답변을 직접 비교한다.

```sh
uv run --locked llm-lab --offline --model qwen3-4b \
  --corpus-dir data/runbooks --retriever scoped-v3 \
  --prompt-variant grounded-v3 \
  --temperature 0 --max-tokens 256 --seed 42 \
  --prompt '우리 팀에서 재시도 횟수를 제한해야 하는 이유는?'
```

전체 개발셋 비교는 다음과 같다.

```sh
uv run --locked python -m llm_ops_lab.evaluation --offline \
  --model qwen3-4b --retriever scoped-v3 --prompt-variant baseline \
  --temperature 0 --max-tokens 256 --seed 42

uv run --locked python -m llm_ops_lab.evaluation --offline \
  --model qwen3-4b --retriever scoped-v3 --prompt-variant grounded-v3 \
  --temperature 0 --max-tokens 256 --seed 42
```

추가 20문항은 각각 `--dataset data/eval/retrieval-challenge-v1.jsonl`을 붙여 실행한다.
배치를 동시에 실행하지 않는다. 자동 요약은 검색·실행 결과만 보여 주므로 내용을 별도로 검토한다.
이번 실행의 원본 `review.md`와 `summary.json`은 보존하고 `review.assistant.md/json`을 별도로 작성했다.

기본값은 유지했으므로 롤백 작업이 필요하지 않다. 후보를 명시해 사용했다면
`--prompt-variant baseline`으로 돌아갈 수 있다. 실패한 추론 기록은 삭제하거나 덮어쓰지 않는다.

이번 실험에서 배울 점은 “지시를 더 자세히 쓰면 모든 답변이 좋아진다”는 가정을 검증하는 것이다.
하나의 오류를 고친 뒤에도 이미 통과하던 질문을 다시 확인해야 변경을 평가할 수 있다.
