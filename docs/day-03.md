# 질문으로 문서를 고르는 검색 기준선

## 두 가지 실행

먼저 모델을 실행하지 않고 검색 결과만 확인합니다.

```sh
uv run --locked llm-lab --corpus-dir data/runbooks --search-only \
  --prompt '일시적인 API 오류의 재시도 간격과 최대 시도 횟수는?'
```

선택한 문서를 모델에 전달하려면 search-only를 제외합니다.

```sh
uv run --locked llm-lab --offline --corpus-dir data/runbooks \
  --prompt '일시적인 API 오류의 재시도 간격과 최대 시도 횟수는?' \
  --temperature 0 --max-tokens 256 --seed 42
```

`--context-file`은 사용자가 정한 문서 한 개를 읽고, `--corpus-dir`은 프로그램이 문서를 고릅니다.
두 옵션은 동시에 사용할 수 없습니다. `--search-only`는 corpus-dir과 함께 사용합니다.

## 검색이 하는 일

1. 폴더 바로 아래 .md/.txt 파일을 정렬해 최대 32개 읽습니다. 파일당 기존 16 KiB 계약을 적용합니다.
2. 자주 쓰는 조사 일부를 제거하고, 한글은 두 글자씩, 영문은 단어 단위로 비교합니다.
3. 여러 문서에 흔한 표현보다 적은 문서에 등장하는 표현에 더 큰 가중치를 줍니다.
4. 본문에서 찾은 질문 표현의 가중치 비율 80%와 첫 줄의 비율 20%를 합산해 정렬합니다.
5. 본문 겹침 비율이 0.5 미만이거나 매칭 표현이 너무 적으면 선택하지 않습니다.
   질문 표현이 둘 이상이면 최소 두 개 매칭을 요구합니다. 2위 점수가 1위의 95% 이상이면
   모호하다고 판단해 선택을 보류합니다. 동점에서 파일명 순으로 억지 선택하지 않습니다.

가중치는 `1 + log((문서 수 + 1) / (표현이 등장하는 문서 수 + 1))`입니다.
비율의 분모에는 문서에서 찾지 못한 질문 표현도 포함합니다. 점수는 정답 확률이 아닙니다.
임계값과 조사·일반 표현 규칙은 작은 개발 예제를 위한 휴리스틱이며 일반 검색 품질을 보장하지 않습니다.
정교한 형태소 분석, 임베딩, 동의어 이해는 구현하지 않았습니다.

## 실패 처리와 변경 반영

검색 결과 없음·겹침 부족·모호함이면 Python이 모델 호출 전에 답변을 보류합니다.
이 경로와 search-only는 모델 라이브러리 import·다운로드·GPU 할당을 하지 않습니다.
아무 문서를 고르지 못했다고 실제 관련 지식이 존재하지 않는다는 뜻은 아닙니다. 검색기 한계일 수 있습니다.
허용 확장자의 손상된 파일 하나라도 있으면 검색 전체가 오류로 끝납니다. 조용히 제외해 부분 결과를 만들지 않습니다.

매 요청마다 현재 파일을 다시 읽으므로 수정·삭제가 다음 요청에 반영됩니다. 영구 검색 인덱스는 없고,
이 방식은 작은 폴더에 한정합니다. 커지면 인덱스 구축·원자적 버전 전환·복구가 필요합니다.
여러 파일을 읽는 동안 외부에서 동시에 편집하면 하나의 시점에 대한 원자적 스냅샷은 보장하지 않습니다.
실험 중에는 문서 편집을 마친 뒤 실행하고, 각 파일 해시로 실제 읽은 내용을 추적합니다.

## 기록과 평가

새 실행은 inference-experiment.v2로 저장하며 기존 v1 파일을 변경하지 않습니다.

- `status`: generated / search_only / abstained.
- `model_executed`: 실제 생성했는지. 검색/보류는 false이고 model_id/model_revision은 null입니다.
- `retrieval`: 검색기·토큰화 버전, 질문 표현, 상위 후보 점수와 매칭 표현, 선택/보류 이유.
- `retrieval.corpus_manifest`와 `corpus_sha256`: 문서 목록·각 내용 해시와 집합의 식별 값.
- `sources`와 `messages`: 실제 생성에 사용한 문서·본문. 검색만 실행하거나 보류하면 빈 배열입니다.

검색만/보류 기록에는 생성 토큰·생성 시간·모델 메모리 필드가 없습니다. 읽는 쪽에서 0으로 단정하지 않습니다.
모든 요청의 UUID 기록을 보존하며, 같은 내용을 다시 읽었다고 실행 기록을 덮어쓰지 않습니다.

개발용 예제 6개는 `data/eval/retrieval-smoke.jsonl`에 있습니다.
멱등성·재시도·백필 3개 선택, 범위 밖/일반적 질문 3개 보류를 확인합니다.
알고 있는 소수 예제를 대상으로 만든 smoke 검사이며, 잠금 평가셋이나 일반 정확도 측정이 아닙니다.
검색 통과와 답변 정확도는 별개입니다. 올바른 문서를 선택해도 작은 모델이 내용을 왜곡할 수 있습니다.
