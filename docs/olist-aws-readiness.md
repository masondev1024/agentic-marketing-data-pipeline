# AWS 이전 판단

상태: 설계 검토 자료. AWS 리소스 생성·배포·비용 검증은 수행하지 않았다.

현재 `InferenceRuntime`은 코드에서 Darwin/arm64를 요구하며 선택 의존성도 같은 환경에
한정한다. 현 서비스를 Linux 컨테이너로 복사해 바로 운영할 수 있다고 가정하지 않는다.
이는 이 프로젝트의 구현 제약이며 MLX 전체의 Linux 지원 여부에 대한 주장이 아니다.

우선 제안은 데이터 계층을 S3 원본/매니페스트, PostgreSQL 마트, 컨테이너 배치 및 API,
CloudWatch 실행 관측으로 옮기고 모델은 별도 추론 어댑터로 분리하는 것이다.
관리형 모델 호출은 GPU 상시 비용을 피할 수 있으나 호출 비용, 재현성, 모델별 출력 품질을
다시 검증해야 한다. 자체 Qwen 운영은 모델 비교의 일관성을 얻는 대신 GPU 런타임·용량·패치와
장애 대응 부담이 늘어난다. 작은 포트폴리오의 첫 클라우드 검증에는 관리형 추론을 우선 검토한다.

Bedrock은 모델마다 지원 지역과 호출 방식이 다르므로 계정·지역을 정한 후
[공식 모델 지원표](https://docs.aws.amazon.com/en_us/bedrock/latest/userguide/models.html)를
확인한다. cross-Region inference를 사용하면
[라우팅 범위와 권한](https://docs.aws.amazon.com/bedrock/latest/userguide/inference-profiles-support.html)도
별도 결정한다. 특정 모델이나 서울 리전 지원을 아직 확정하지 않았다.

실제 프로비저닝 전에 다음이 확정되어야 한다.

- 로컬 실제 모델/API 평가 통과와 거절·오류 사례의 검토 결과.
- 계정, 리전, 월 예산 및 실험 종료일, 자원 삭제와 백업 보존 범위.
- 모델/provider 버전과 최대 호출량, 외부 전송 가능한 집계 데이터 범위.
- 비공개 DB, 읽기 역할, 비밀 저장소, TLS·인증·요청량 제한. 현재 loopback 전용 API는
  인터넷 공개용 인증이 없으므로 단순 포트 개방을 하지 않는다.
- 원본 해시와 게시 버전 이전, 백업 복원, 배치 중단·재실행, 이전 정상 버전 유지 검증.
- Linux 빌드와 추론 어댑터, 큐/재시도 중복의 처리 계약 및 비용 알람 검증.

검토 결과를 바탕으로 Terraform plan과 예상 비용·보존/삭제 범위를 먼저 제시한다.
사용자의 명시적인 승인 전에는 apply나 유료 모델 호출을 실행하지 않는다.
